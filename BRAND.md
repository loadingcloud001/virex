## Name: Virex

**Pronunciation**: `VY-rex` (like Tyrannosaurus rex)

**Composition**:
- `vi` — Latin prefix for "vision" / "video" / "visual"
- `rex` — Latin for "king" / "ruler"

**Meaning**: "King of Vision" — implies leadership and dominance in the AI vision space.

**Character count**: 5 (single word, memorable)

---

## Why This Name

### 1. Unique
- Verified clean on GitHub (no existing repo conflicts)
- Verified clean on Google (no major commercial product)
- No existing software trademark in video surveillance space
- Free for Loading Cloud to claim as a product brand

### 2. Memorable
- Two syllables (VY-rex) — easy to say
- Echoes "T-Rex" — immediately vivid mental image
- 5 characters — fits in URLs, logins, package names
- Phonetically intuitive — non-English speakers can pronounce it

### 3. Brandable
- Logo possibilities:
  - "V" with sharp angles (predator imagery)
  - "X" as the crosshair / target reticle
  - Rex silhouette integrated with eye/camera lens
- Color palette options: Deep black + electric blue, or stealth gray + alert red
- Versatile for both B2B professional and developer-focused branding

### 4. Sustainable (won't trap us)
- Does NOT contain: "video", "camera", "stream", "CCTV", "Frigate"
- Does NOT depend on: AI model names, deployment model, hardware
- Works across product evolution:
  - Phase 1: Multi-tenant VMS with Frigate backend
  - Phase 2: Add OCR, segmentation overlay
  - Phase 3: Multi-node cluster, advanced analytics
  - Phase 4: Multi-modal AI (video + audio + sensors)
- Works across business evolution:
  - SaaS → Enterprise license → On-premise → API platform

### 5. International
- Pronounceable in: English, Mandarin, Cantonese, Japanese, Korean, Spanish, German
- No negative connotations in major languages
- Suitable for global B2B expansion

## Brand Architecture

### Product Brand (Customer-Facing)
```
Virex™
AI-Powered Multi-Tenant Video Surveillance
```

Used in:
- Customer-facing UI (logo, login pages)
- Marketing materials
- Customer email signatures
- Domain: virex.app (planned)

### Company Brand (Trust Anchor)
```
A Virex by Loading Cloud product
Maintained by Loading Cloud
```

Used in:
- Footer of customer portal
- GitHub README
- Legal documents (LICENSE)
- Investor materials
- "About" pages

### Development Identity (Developer-Facing)
```
github.com/loading/virex
docker: loading/virex-portal
PyPI: virex
```

Used in:
- Source code commits
- Docker images
- Python packages
- Issue tracking

This three-tier approach lets us:
1. **Sell** as "Virex" (professional, no founder name baggage)
2. **Trust** as "Loading Cloud" (real company behind it)
3. **Trace** as "loading/virex" (founder accountable in code)

## Loading Cloud Identity

**Loading Cloud** is the parent company / brand behind Virex.

The name "Loading Cloud" reflects:
- **Loading** — founder's name; suggests patience, anticipation, the moment before something arrives
- **Cloud** — the deployment model; suggests scale, accessibility, no local hardware burden

Loading Cloud Ltd. (Hong Kong) owns and operates:
- **Virex** (current product, Phase 1+)
- Future products (Phase 4+) under separate sub-brands

The founder's GitHub username is `loading`, which appears in all repo URLs.
